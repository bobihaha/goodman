# 物联网卡平台审计修复说明（2026-09-05）

## 修复范围

本轮优先处理已复现、可在现有架构内安全修复的问题：

- 用户资料、余额、状态、密码和权限接口的越权边界。
- 系统私密配置的读取和修改权限。
- 供应商回调的来源鉴权、失败回调、重放和过期操作保护。
- 密码修改、密码重置和退出登录后的旧令牌失效。
- H5 开启验证码但服务尚未实现时的绕过问题（暂时失败关闭）。
- 停复机日志和告警处理的租户隔离，以及供应商原始响应脱敏。
- 月初供应商旧月份用量与新月份额度混算；同步源时间与抓取时间分离。
- 用量告警保存触发时快照和告警时间，汇总邮件仅展示本月告警轨迹。
- 年包月累计与叠加包重复累加、余额扣减与补量事务不一致。
- 非整除分钟调度错误、超量卡全表加载和 ECharts 实例泄漏。
- 历史用量导出加载全部日快照、同步构建 Excel 阻塞事件循环，以及卡片 API 重复注册。
- 出库失败卡被误写销售价，升级后端存在已知安全公告的依赖版本。
- Docker 构建上下文排除环境文件、证书、备份和前端源码，避免敏感文件进入镜像层。

## 数据与兼容策略

- `sys_users.token_version` 初始为 `0`。迁移前签发且不带版本号的令牌，仅在版本仍为 `0` 时兼容；改密、重置密码或退出登录后统一失效。
- `iot_cards.data_source_at` 保存供应商快照时间，`data_usage_month` 保存该用量所属月份；`data_sync_at` 继续表示平台抓取时间。
- 月包用量只接受当前流量周期的供应商快照。来源时间缺失或仍属于上月时，本月展示用量归零并标记为待有效同步，不触发用量告警或停机。
- 已有卡的新字段允许为空，待下次有效同步补齐；为空的月包不会被计入本月池用量。
- H5 用户开启 `h5_require_verify` 后，在验证码服务正式接入前暂停停机、复机和重启操作，避免配置形同虚设。

## 发布前置条件

- 执行数据库迁移 `20260905_add_security_and_usage_period_fields.sql`。
- 配置高强度 `UPIOT_CALLBACK_TOKEN`，并在供应商回调请求头 `X-UPIOT-Callback-Token` 或查询参数 `token` 中携带同一值。
- 明确设置 `DEBUG=false`；生产环境若显式开启 DEBUG，应用应拒绝启动。
- 先在隔离数据库完成后端测试、前端类型检查与构建，再按稳定发布手册执行备份、发布和回滚准备。

## 暂不纳入本轮

- 历史快照批量 upsert、超大文件异步任务化等结构性性能重构；本轮已限制历史导出为 2,000 张卡、24 个月，并在数据库内按月取最后快照。
- 其余未检出已知漏洞的前端依赖升级；前端本轮 `npm audit` 结果为 0 个已知漏洞。
- 购买补量接口的持久化幂等订单模型；本轮先保证单次请求内余额、额度与日志的事务一致性。
