# 模块责任边界与改动影响面

这份文档用于帮助维护者快速判断：

- 某个功能属于哪个模块负责
- 改动某个模块时，通常会联动到哪些代码位置
- 哪些改动最容易产生跨模块回归

它不是需求文档，也不是 API 文档，而是面向日常维护、改需求、排障和发版评审的“影响面地图”。

## 1. 如何使用这份文档

遇到需求或 bug 时，建议按这个顺序看：

1. 先找到功能归属模块
2. 再看该模块的责任边界
3. 根据“高频联动模块”检查影响面
4. 按“修改时至少检查”列表做回归

如果一个改动同时跨越“权限 + 数据结构 + 定时任务 + 前端页面”，默认按高风险改动处理。

## 2. 全局分层边界

### 前端

- `frontend/src/views/`
  - 页面入口、页面状态、交互编排
- `frontend/src/components/`
  - 可复用组件与对话框
- `frontend/src/api/modules/`
  - 前端 API 封装
- `frontend/src/types/`
  - 前端字段类型定义
- `frontend/src/router/`
  - 路由、菜单访问、守卫
- `frontend/src/stores/`
  - 全局登录态和基础状态

### 后端

- `app/api/v1/`
  - 路由定义、参数接收、响应封装
- `app/services/`
  - 核心业务逻辑
- `app/crud/`
  - 查询、持久化、数据聚合
- `app/db/models/`
  - 表结构与关系映射
- `app/schemas/`
  - 请求/响应模型
- `app/clients/`
  - 供应商外部接口
- `app/scheduler.py`
  - 定时任务编排

### 边界原则

- 路由层不要堆业务规则，复杂逻辑应落在 `services`
- 前端页面不直接拼接口，统一经过 `src/api/modules`
- 表结构变更不能只改模型，要同步检查 schema、service、API 和前端类型
- 任何涉及供应商同步、停复机、池统计的改动，都要额外检查调度任务与回调逻辑

## 4. 各模块责任边界

### 4.1 认证与登录

负责：

- 用户登录、退出、Token 刷新
- 当前用户资料获取
- 超级登录入口

不负责：

- 用户增删改本身
- 菜单装配策略
- 业务数据权限过滤细节

高频联动模块：

- 用户/权限/菜单
- 路由守卫
- 超级登录 Banner 和前端登录态

修改时至少检查：

- 登录页
- `frontend/src/stores/modules/auth.ts`
- `frontend/src/router/guards.ts`
- 当前用户资料接口是否返回新增字段

### 4.2 用户 / 权限 / 菜单

负责：

- 三级用户体系
- 用户创建、编辑、禁用、重置密码
- 角色权限、菜单可见性、按钮权限

不负责：

- 具体业务模块里的数据规则
- 卡片、库存、流量池的业务计算

高频联动模块：

- 认证模块
- 路由与动态菜单
- 所有页面的按钮显隐
- 项目管理、H5 配置、超级登录

修改时至少检查：

- 用户列表和用户表单
- 菜单加载接口
- 路由守卫
- 权限指令 `frontend/src/directives/permission.ts`
- 至少一个超管账号和一个普通用户账号的页面差异

### 4.3 卡片管理

负责：

- 卡片列表、详情、搜索
- 备注、划拨、批量操作
- 单卡和批量续费、加油包、导出

不负责：

- 采购入库和库存归档
- 供应商主数据维护
- 流量池底层统计计算规则本身

高频联动模块：

- 出入库
- 流量池
- 停复机
- 项目管理
- H5 门户
- 仪表盘

修改时至少检查：

- 卡片列表筛选
- 卡片详情
- 批量操作弹窗
- 导出
- 与卡状态相关的仪表盘或停复机列表

### 4.4 套餐管理

负责：

- 底层套餐维护
- 销售套餐维护
- 套餐规格字段定义

不负责：

- 实际库存导入动作
- 卡片状态同步

高频联动模块：

- 出入库
- 流量池自动组池
- 卡片详情展示
- 仪表盘统计口径

修改时至少检查：

- 供应商套餐列表
- 销售套餐列表
- 出库表单中的套餐选择
- 流量池规格匹配逻辑

### 4.5 供应商管理

负责：

- 供应商资料
- API 地址、密钥等接入参数
- 同步频率等供应商配置

不负责：

- 卡片业务状态的最终展示逻辑
- 定时任务整体编排

高频联动模块：

- 同步与调度
- 停复机
- 供应商回调
- 出入库

修改时至少检查：

- 供应商列表
- 同步任务是否仍可加载
- 供应商 API 客户端入参
- 回调数据能否匹配到正确供应商

### 4.6 出入库管理

负责：

- 批量入库
- 批量出库
- 库存卡片查询
- 回收和记录归档

不负责：

- 用户前台卡片自助操作
- 供应商 API 本身

高频联动模块：

- 卡片管理
- 套餐管理
- 供应商管理
- 项目管理

修改时至少检查：

- 入库流程
- 出库流程
- 库存列表
- 回收流程
- 出入库记录和卡片归属是否一致

### 4.7 流量池

负责：

- 流量池创建与维护
- 池内卡片管理
- 池统计与阈值相关逻辑
- 加油包/附加流量

不负责：

- 单卡明细的原始同步来源
- 停复机策略配置页面本身

高频联动模块：

- 卡片管理
- 停复机
- 同步与调度
- 仪表盘

修改时至少检查：

- 池列表
- 池详情
- 池加卡和移卡
- 池统计刷新
- 超阈值后的停卡联动

### 4.8 停复机

负责：

- 停卡策略
- 手动停卡/复机
- 停卡日志
- 停卡告警

不负责：

- 供应商主数据
- 登录权限

高频联动模块：

- 卡片管理
- 流量池
- 供应商客户端
- 回调与状态修正

修改时至少检查：

- 策略列表
- 停复机按钮
- 告警列表
- 卡状态是否同步回到卡片列表和仪表盘

### 4.9 同步与调度

负责：

- 定时任务加载
- 用量同步
- 生命周期刷新
- 与供应商 API 的周期性数据拉取

不负责：

- 手工维护供应商参数
- 页面展示文案

高频联动模块：

- 供应商管理
- 卡片管理
- 流量池
- 停复机
- 仪表盘
- 回调处理

修改时至少检查：

- `app/main.py` 的启动加载逻辑
- `app/scheduler.py`
- 同步任务是否重复注册
- 关键状态字段是否仍能正确刷新

### 4.10 仪表盘

负责：

- 首页聚合统计
- 告警、余额、异常卡片汇总展示

不负责：

- 原始业务数据写入
- 细粒度业务规则定义

高频联动模块：

- 卡片管理
- 流量池
- 停复机
- 账户余额

修改时至少检查：

- 首页卡片统计
- 到期卡列表
- 超量卡列表
- 运营商筛选和汇总口径

### 4.11 系统设置

负责：

- 系统配置
- 日志面板

不负责：

- 具体业务实体本身

高频联动模块：

- 运维排障流程

修改时至少检查：

- 配置表单
- 日志查询
- 是否影响其他模块读取系统配置

### 4.12 项目管理

负责：

- 项目维度数据归属
- 项目列表和项目关联信息

不负责：

- 卡片生命周期本身
- 套餐规格维护

高频联动模块：

- 卡片管理
- 用户管理
- 出入库

修改时至少检查：

- 项目列表
- 卡片归属筛选

### 4.13 H5 门户

负责：

- H5 页面配置
- 用户自助能力开关

不负责：

- 后台用户权限体系

高频联动模块：

- 用户管理
- 卡片管理
- 停复机

修改时至少检查：

- H5 首页

### 4.14 供应商回调

负责：

- 接收供应商异步回调

不负责：

- 主动轮询调度
- 供应商主数据维护页面

高频联动模块：

- 卡片状态
- 停复机

- 同步日志

修改时至少检查：

- 回调接口鉴权或入参
- 回调幂等处理
- 卡片状态回写
- 前端是否能看到最新状态

## 5. 高风险联动关系

下面这些组合一旦改动，最容易出现跨模块回归：

- 卡片状态字段变更
  - 会影响卡片列表、停复机、流量池、仪表盘、H5、回调
- 用户归属字段变更
  - 会影响权限过滤、卡片可见范围、项目归属、出库逻辑
- 套餐规格字段变更
  - 会影响套餐、出入库、流量池组池规则、卡详情展示
- 供应商接口字段变更
  - 会影响同步任务、停复机调用、回调修正、卡状态刷新
- 菜单/权限码变更
  - 会影响路由、按钮权限、用户管理、前端守卫
- 项目字段或关系变更
  - 会影响卡片筛选、出库归属、统计展示

## 6. 常见改动场景与检查清单

### 场景 1：新增一个卡片字段

通常至少要检查：

- `app/db/models/iot_card.py`
- `app/schemas/iot_card.py`
- `app/crud/iot_card_crud.py`
- `app/services/iot_card_service.py`
- 对应 API 返回
- `frontend/src/types/card.d.ts`
- 卡片列表和详情页
- 如果字段与库存、停复机、流量池有关，再检查对应模块

### 场景 2：修改卡状态流转

通常至少要检查：

- 卡片服务
- 停复机服务
- 流量池统计与阈值触发
- 同步任务
- 仪表盘统计
- H5 页面展示
- 供应商回调修正逻辑

### 场景 3：新增菜单或权限

通常至少要检查：

- 菜单表 / 权限表数据
- 后端菜单接口
- 前端路由
- 权限指令
- 用户授权弹窗

### 场景 4：修改供应商同步逻辑

通常至少要检查：

- `app/clients/`
- `app/services/sync_service.py`
- `app/scheduler.py`
- 停复机服务是否复用该逻辑
- 回调和补偿逻辑
- 仪表盘与卡片列表是否看到预期结果

### 场景 5：修改出库逻辑

通常至少要检查：

- 库存扣减
- 卡片归属用户
- 销售套餐关联
- 项目归属
- 卡片列表可见性
- 出库记录

## 7. 回归测试优先级建议

### P0 必测

- 登录
- 菜单加载
- 卡片列表
- 一条核心新增/编辑/批量流程
- 与本次改动直接相关的首页统计

### P1 建议测

- 权限差异账号
- 出入库记录
- 停复机或同步任务相关功能
- 导出/批量操作

### P2 视改动范围补测

- H5 门户
- 回调链路
- 系统设置与日志面板

## 8. 维护建议

后续如果继续沉淀，可以再补两类资料：

- 每个模块的“核心字段清单”
- 每个模块的“常见故障定位路径”

这样后续做线上排障时，就能从“模块边界”继续走到“故障定位”。
