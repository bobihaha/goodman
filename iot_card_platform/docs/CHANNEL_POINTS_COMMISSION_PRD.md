# 渠道推广积分系统 PRD

## 1. 目标

建立独立于现有三级平台用户体系的渠道伙伴系统，形成以下业务闭环：

1. 超级管理员创建渠道伙伴并配置专属客户报备 H5。
2. 客户在渠道专属 H5 提交姓名、手机号、用户情况（设备、场景、规模），无需短信验证码。
3. 系统自动在平台“用户管理”中创建二级用户，并永久记录首次有效渠道归属。
4. 平台向该客户出库、该客户在线购买续费时，实时生成推广积分明细。
5. 渠道伙伴登录独立渠道页面，可查看汇总和具体客户订单积分。
6. 超级管理员配置比例、查看全部明细并确认结算；首版不提供提现、兑换或打款。

本功能不得改变现有平台用户、卡片、出入库、续费、H5 自助服务的访问方式和数据权限。

## 2. 名词与口径

- **渠道伙伴**：独立业务主体，拥有独立账号、密码和客户报备 H5，不属于 `sys_users` 三级用户体系。
- **渠道客户**：通过渠道 H5 首次有效报备后自动创建或锁定的 `sys_users` 二级用户。
- **推广积分**：按订单计佣基数和比例计算的内部统计积分，不表示现金，不提供提现或兑换。
- **出库订单**：现有 `stock_out_records` 中成功出库的卡片明细。
- **续费订单**：客户通过余额购买单卡续费后新增的结构化订单；后台人工批量续费不计积分。
- **待结算**：订单已完成、积分已实时生成，但尚未由超级管理员确认结算。
- **已结算**：超级管理员已确认该积分记录。
- **冲正**：订单撤销或卡片回收后产生的负积分记录。
- **已消耗积分**：首版沿用结算口径，指超级管理员已确认结算的积分。
- **剩余积分**：尚未确认结算的待结算积分；首版不代表可提现或可兑换余额。

积分计算统一使用：

```text
推广积分 = 订单计佣基数（元） × 积分比例（%）
```

示例：订单计佣基数 100 元，比例 5%，产生 5.00 推广积分。

## 3. 首版业务规则

### 3.1 渠道伙伴

- 由超级管理员创建、编辑、启停和重置密码。
- 渠道账号、手机号、H5 `slug` 全局唯一。
- 支持出库积分比例、续费积分比例按渠道覆盖；未覆盖时使用平台默认比例。
- 停用渠道后禁止登录、新增客户报备和新增积分，历史客户归属和积分记录保留。

### 3.2 客户报备与归属

- H5 收集客户姓名、手机号、用户情况和隐私告知确认，不发送短信验证码。
- 用户情况为必填综合描述，至少包含设备类型、使用场景和预计规模，字段名为 `customer_profile`，长度 5～500 字。
- 手机号是首版唯一归属判定键。
- 同一手机号只能存在一个有效渠道归属，首次有效报备锁定。
- 若手机号已存在平台用户但尚无渠道归属，公开 H5 不自动绑定，提示联系平台确认，防止抢占现有客户。
- 自动创建的平台用户：
  - 用户层级为二级用户；
  - 上级为当前有效超级管理员；
  - 账号优先使用 `c + 手机号`；
  - 系统生成不可见随机密码，后续由管理员按现有流程重置；
  - 自动分配现有二级用户默认菜单和权限；
  - 备注记录渠道来源。
- 报备接口记录 IP、User-Agent 和提交时间，用于审计。

### 3.3 比例与历史数据

- 平台配置默认出库比例和默认续费比例。
- 渠道可分别覆盖出库、续费比例。
- 比例范围为 `0%～100%`，最多四位小数。
- 每笔积分写入时保存比例快照；后续修改比例只影响新订单，不重算历史订单。

### 3.4 出库积分

- 仅当目标用户存在有效渠道归属时计积分。
- 每张成功出库卡生成一条积分明细，计佣基数为该卡出库锁定销售单价。
- 同一出库单、同一卡片只允许生成一次正向积分，必须幂等。
- 卡片回收时，对最近一次有效出库积分生成等额负积分冲正明细。

### 3.5 续费积分

- 仅统计客户通过余额完成的单卡续费购买。
- 后台人工批量续费不视为销售订单，首版不计积分。
- 续费成功时先生成结构化 `renewal_orders` 订单，再生成对应积分明细。
- 同一续费订单只允许生成一次正向积分，必须幂等。

### 3.6 结算

- 首版仅支持超级管理员将待结算积分批量确认为已结算。
- 渠道页面可实时查看待结算、已结算、冲正和累计积分。
- 首版不提供提现、积分兑换、打款、发票和税务处理。
- 将佣金命名为积分不自动构成合规结论；后续如开放兑换或权益，应另行完成法务和财税评估。

## 4. 页面范围

### 4.1 超级管理员“渠道积分管理”

- 平台默认比例设置。
- 渠道伙伴列表：名称、联系人、账号、状态、客户数、H5 地址、比例覆盖。
- 新增/编辑渠道、重置密码、启停、复制 H5 地址。
- 全部积分明细：渠道、客户、手机号、订单类型、订单号、卡号、基数、比例、积分、状态、时间。
- 按渠道、客户、订单类型、状态、日期筛选。
- 批量确认结算待结算记录。

### 4.1.1 超级管理员“用户管理”联动

- 超级管理员查看一级平台用户列表时，增加“推荐渠道”列，展示正式渠道归属关系中的渠道名称；无渠道归属显示“—”。
- 支持按推荐渠道筛选一级平台用户。
- 一级平台用户登录后查看自己的下级用户列表时，不展示推荐渠道列，不加载渠道选项，也不改变原有查询行为。

### 4.2 渠道客户报备 H5

- 展示渠道名称和报备说明。
- 输入客户姓名、手机号、用户情况（设备、场景、规模）。
- 必须勾选隐私告知确认。
- 成功后显示已完成登记，不展示平台初始密码。
- 重复手机号给出明确提示，不重复创建用户。
- 提交失败必须显示明确原因；前端校验失败时定位到对应必填项，禁止出现点击无反馈。
- 页面提供渠道伙伴登录入口，但公开页面不得展示推荐客户和积分数据。

### 4.3 渠道积分页面

- 独立渠道登录。
- 汇总卡：客户数、累计积分、已消耗积分（已结算）、剩余积分（待结算）、本月积分。
- 推荐客户：姓名、手机号、用户情况、报备时间、订单积分笔数、累计积分、已消耗积分、剩余积分。
- 积分明细：具体客户姓名和手机号、订单类型、订单号、卡号、计佣基数、比例、积分、状态、下单时间。
- 支持客户、订单类型、状态、日期筛选和分页。

## 5. 数据设计

### 5.1 `channel_partners`

- 渠道名称、联系人、手机号。
- 独立登录账号和密码哈希。
- H5 `slug`、报备开关、状态。
- 出库和续费比例覆盖值，可为空。
- 最近登录时间、创建人。

### 5.2 `channel_commission_settings`

- 平台默认出库比例。
- 平台默认续费比例。
- 更新人和更新时间。

### 5.3 `channel_customer_relations`

- 渠道 ID、平台用户 ID。
- 客户姓名、手机号快照。
- 用户情况 `customer_profile`；历史数据允许为空，新提交必须填写。
- 归属状态、来源、报备 IP、User-Agent、报备时间。
- 手机号和平台用户 ID 均保持唯一有效归属。

### 5.4 `renewal_orders`

- 订单号、用户、卡片、ICCID。
- 续费月数、单价、订单总额。
- 完成状态、完成时间、操作人。

### 5.5 `channel_point_ledger`

- 渠道、渠道客户关系、平台用户。
- 客户姓名和手机号快照。
- 正向/冲正类型，出库/续费订单类型。
- 来源订单 ID、订单号、卡片 ID、ICCID。
- 计佣基数、比例快照、积分。
- 待结算/已结算状态、结算人和结算时间。
- 关联原积分记录，用于冲正审计。

## 6. 接口范围

统一前缀：`/api/v1/channels`

公开接口：

```text
GET  /public/{slug}
POST /public/{slug}/register
```

渠道接口：

```text
POST /auth/login
GET  /me
GET  /me/summary
GET  /me/customers
GET  /me/points
```

超级管理员接口：

```text
GET  /admin/settings
PUT  /admin/settings
GET  /admin/partners
POST /admin/partners
PUT  /admin/partners/{id}
POST /admin/partners/{id}/reset-password
GET  /admin/points
POST /admin/points/settle
```

## 7. 安全与兼容边界

- 渠道 JWT 必须包含独立主体类型，平台用户接口必须拒绝渠道 Token。
- 渠道只能查询自己名下的客户和积分，不能访问平台卡片、用户、库存等接口。
- 公开报备接口不返回用户账号、密码、内部用户 ID 等敏感信息。
- 姓名和手机号在渠道页面只对其归属渠道展示。
- 无短信验证会增加恶意或错误报备风险；首版依靠手机号唯一、渠道启停和审计记录控制，后续可增加图形验证码和访问频率限制。
- 所有金额和积分使用 `DECIMAL`，禁止用浮点数落库计算。
- 数据库迁移只新增表和菜单，不修改现有业务字段，保证未启用时对日常平台无影响。

## 8. 首版验收标准

- 超管可以创建渠道、设置默认和渠道覆盖比例、复制渠道 H5。
- H5 提交后平台用户列表出现新用户，手机号重复不会产生第二个用户。
- H5 缺少用户情况时不能提交；提交失败有可见反馈。
- 渠道登录后可按客户查看用户情况、累计、已消耗和剩余积分，公开推荐链接无法访问这些数据。
- 向渠道客户成功出库后，渠道页面立即出现逐卡积分明细。
- 渠道客户在线续费成功后，产生结构化续费订单和积分明细。
- 修改比例后，旧积分比例不变，新订单使用新比例。
- 渠道只能看到自己的客户和积分。
- 超管确认结算后，渠道页面状态和汇总同步变化。
- 卡片回收后生成对应负积分冲正记录。
- 未绑定渠道的客户出库和续费行为保持原样，不产生积分。
