# 续费后套餐周期被回写事故记录

## 时间

- 发现时间：2026-04-27
- 处理完成时间：2026-04-28

## 影响对象

- `89860862102590436070`
- `89860862102590436071`
- `89860862102590436072`

## 现象

- 用户反馈三张卡已经续费，但套餐周期没有延长。
- 页面上表现为续费后到期日没有按预期保留。

## 线上实际情况

通过生产库核对发现：

1. 三张卡在 `2026-04-27 09:41` 已经续费成功。
2. 续费日志显示到期日已从 `2027-10-31` 延长到 `2027-11-30`。
3. 后续在 `2026-04-27 10:00:31` 被生命周期同步重新写回成 `2027-03-31`。

结论：

- 不是“续费根本没生效”。
- 真正问题是“续费成功后，本地更长到期日被后续同步覆盖写短”。

## 根因

### 根因 1：生命周期同步未保护本地更长到期日

文件：

- [app/services/sync_service.py](/Users/renhui/Documents/GitHub/goodman/iot_card_platform/app/services/sync_service.py)

问题：

- 同步供应商生命周期时，直接用供应商返回的 `expired_at` 覆盖本地值。
- 当本地因续费已是更长周期，而供应商侧仍返回旧周期时，会把本地到期日写短。

修复：

- 增加“保留本地更长到期日”的判断。
- 只有供应商到期日更长或本地为空时才覆盖。

### 根因 2：父账号后台续费下级卡时，范围过滤过严

文件：

- [app/services/iot_card_service.py](/Users/renhui/Documents/GitHub/goodman/iot_card_platform/app/services/iot_card_service.py)

问题：

- 批量续费按 `user_id == 当前账号` 精确过滤。
- 父账号给下级用户名下卡片做后台续费时，可能得到 `0` 成功。

修复：

- 改为走统一的“当前账号可见范围”查询逻辑。

### 根因 3：前端把 `0` 成功误报为成功

文件：

- [frontend/src/views/cards/list/components/SingleRenewDialog.vue](/Users/renhui/Documents/GitHub/goodman/iot_card_platform/frontend/src/views/cards/list/components/SingleRenewDialog.vue)

问题：

- 单卡后台续费分支即使 `result.success == 0`，也会提示“后台续费成功 0 张”。

修复：

- `0` 成功时直接抛出失败提示，展示后端返回的第一条错误原因。
